Try it

Type to grow the box; the send button turns on once there is text. Enter sends, Shift + Enter adds a new line. “Show Typing state” swaps the field for the slot, as Figma’s State=Typing does.

Chat Bar vs .Bottom Bar — differences

  • Default (both themes) and Active · Light: Chat Bar stacks the text row above an actions row (76px tall, padding 10/15, rows space-between with gap 10). .Bottom Bar is one row: + · divider · text · send (54px, padding 0/15).
  • Light placeholder “Search here”: Chat Bar #313131 (--text-dark), .Bottom Bar #545454 (--text-medium). Dark is #D5DAF4 in both.
  • Chat Bar Default uses the .Query Text instance for the placeholder; .Bottom Bar Default uses a plain text layer.
  • Active · Dark, Typing · Light and Typing · Dark are the same one-row layout in both sets.
  • .Bottom Bar Default · Light: the Inputs frame is 640 wide with the send pushed right by space-between; Dark puts send inside the Inputs row. Same look.

Usage

Behaviour

  • Typing grows the field (no max height in Figma).
  • Send turns on once the field has text: blue (Light) or green (Dark).
  • Enter sends · Shift + Enter adds a new line (same rule as the Chat Input Box documentation).
  • + has no destination in Figma; it fires pds-ai-composer:add.
  • Typing state swaps the field for the slot and disables send.

Composition

  • The AI chat window and the action popup place this bar at the bottom and the Prompt above an empty chat.
  • Typing dots, bubbles and the slot come from AI Chat bubbles and Comments.

When (not) to use

No guidance in Figma.

Accessibility

Labels

Field is a <textarea> labelled “Message” (pass label). + is a button “Add”, send a button “Send” with native disabled while empty. Prompt cards are buttons.

Focus — added in review, not in Figma

2px solid --pando-blue, offset 2, on the bar while the field has focus, and on +, send and cards.

Open for the accessibility pass

Dark Active text #313131 on the 40% Pando Dark bar ≈ 1.6 : 1 over white. Light send off #FFF on #CBD4D8 ≈ 1.5 : 1. Light send on (blue) 4.6 : 1, Dark on (green) #FFF on #1FCD93 ≈ 2.0 : 1. Dark placeholder #D5DAF4 on the bar over white ≈ 1.6 : 1. Prompt label #545454 on white 7.5 : 1.

Open issues

  • Active · Light send: Chat Bar and .Bottom Bar override the Button to #0076DD (Pando Blue) instead of using .send, whose main Active · Light is #FE6505 (Freehand Orange). Built blue in the bar; orange kept as .pds-ai-composer__send--orange.
  • Chat Bar is half-updated: Default (both) and Active · Light are stacked; Active · Dark and Typing are still one row. The live bar stays stacked when Dark turns active.
  • Active · Dark text is #313131 on the dark bar (unreadable). Kept as Figma.
  • Typing state shows only the “Swappable Content” placeholder. What goes in it (typing dots? the responding text?) is not defined; no stop button.
  • + has no menu or destination in Figma.
  • No max height / scroll rule for long text; no hover, focus or disabled state for the bar.
  • Off-token: #9CB3BF 50% divider.
  • Line heights: text and placeholder 12/auto (built 16); SemiBold 12 is 12/17 in tokens; italic has no type style. Prompt intro 10/auto (built 14), cards 10/12 without the 0.5 tracking of .type-10-regular (tracking not read).
  • Prompt (2819:1891) is a 720 × 554 clipped frame aligned to the bottom: the intro and cards sit above the clip, and what shows is the local “CT- Shipper” conversation. Built here: intro + cards. The conversation belongs to the chat window (see the md for what was read).
  • Prompt cards: click target undefined (fires pds-ai-composer:suggest). Fixed 56 height clips the 4-line first card in Figma too.
  • Input atom not used: Figma uses .Query Text (a plain text layer), not Input - Text.
  • .typing light main padding is 8/20; the kit dots (ai-chat-bubbles) use the 8/15 instance override.
  • Loose “Tip: Use # to tag parameters and / to define locations” frame on the page — no # or / behaviour built.
