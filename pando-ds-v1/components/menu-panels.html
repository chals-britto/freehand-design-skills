Usage

Subheader Menu

Figma has no usage text. The loose “Dropdown Subheader” frame on the same page shows it under a subheader title (“All Masters”) listing the pages of a section. Built as a single-select list: picking one closes the menu.

Sort-1

Figma has no usage text. The component is a “Filter By” panel: one choice per group (Indent Type, Delivery Type), with a FTL / PTL Toggle Tab on Delivery Type. It has no sort direction (ascending / descending) — that appears only in loose frames.

Built from

  • List: Dropdown Menus (pdsMenu.build type single + attach), with token overrides.
  • Toggle: Toggle Tab (Atoms, .pds-toggle-tab--dark).
  • Icons: Icons — Status/Indent Type, Navigation/Dropdown-Arrow.

Accessibility

Subheader Menu

The trigger is a button with aria-haspopup="listbox" and aria-expanded; focus stays on it and aria-activedescendant points at the highlighted option (menu.js). The keyboard highlight gets a 2px #0076DD inside outline, because hover and Active share the same fill (added — not in Figma).

Sort-1

The “Filter By” tab is a button with aria-expanded / aria-controls. Each group is a radiogroup labelled by its section header; one tab stop per group (roving tabindex). The Toggle Tab is its own radiogroup (toggle.js). Esc closes and returns focus to the tab.

Open for the accessibility pass

Active fill #E9F1F5 on white 1.14 : 1. Option icon #8A8A9E on #24242F 5.0 : 1 (fine for text-size icons); green arrow #1FCD93 on #24242F decorative. Selected vs unselected Sort-1 text (#FFFFFF vs #D5DAF4) differ by colour only.

Open issues

  • Sort-1 has no selected state in Figma (hidden Radio instances and hidden red “Reset” rows exist). Selected text = white is borrowed from the loose “Sort Dropdown” frame 2312:5531 — confirm.
  • Sort-1 is named “Sort” but is a “Filter By” panel; no ascending / descending control. Loose frames show other sort patterns (Order By with ✓ + “clear”, Sort By A–Z / Z–A, Sort-4 with sort icons).
  • Subheader Menu: Active=Option 1 shows the up arrow, Options 2 and 3 show the down arrow while the list is open. Built: up when open, down when closed.
  • Subheader Menu trigger label is the same in all variants (“Subheader Active”). Whether it should show the picked option is not drawn; showValue option off by default (the Try it uses it, following loose frame 2312:5555).
  • No hover state for Subheader options; menu.css hover (#E9F1F5) is the same as Active, so the keyboard highlight adds an outline (added).
  • Trigger is 216 wide, list 215 (as in Figma). 8 option slots in Figma (5 hidden): max height set to 8 rows (289px).
  • Line heights: option text Figma auto (16) vs 17 in .type-12-semibold (Sort-1 uses a 16px token; Subheader rows are fixed at 36). Tab text 10 SemiBold auto (14) vs 12 in .type-10-semibold.
  • Toggle Tab instance hugs its text (40 / 41 wide); kit option is 69 fixed — overridden with --toggle-tab-option-w: auto inside this component.
  • Tab arrow is a raw vector (7px line, arrow-lines cap, #1FCD93), not an icon — drawn inline.

Industry gaps — not added

  • Sort direction (unsorted / ascending / descending) on a sort control. Carbon Data table
  • Group dividers between selection groups, and radio vs checkbox items to signal single vs multiple choice. Fluent 2 Menu
  • Clear / reset of a group's choice (hidden “Reset” rows exist in Sort-1, not adopted).
