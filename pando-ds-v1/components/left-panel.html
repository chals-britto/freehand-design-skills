Left Menu Panel

The left menu helps for the user to access/navigate different modules or sections within an application. It remains anchored to the left side of the screen, offering users easy, persistent access to high-level features, configurations and settings.

Try it

Collapse / Expand the panel, open and close the stage with Tertiary items, click a row to make it active. Keyboard: ↑ ↓ Home End move between rows, → opens a stage or enters it, ← closes it or goes back to the stage.

Usage

Text from the Figma documentation frame.

Usage

  • Setup/masters sub group navigation
  • Transaction screens navigation between different stages

Placement & convention

It remains anchored to the left side of the screen.

Interaction

  • Primary menu have Hover interaction
  • Inner stage menu have expand & Collapse interaction

Animation: NA (Figma).

Types

  • Menu — Tab Group header over a list of .Menu-Items (one Active, white).
  • Internal Stages — heading + Collapse, Primary rows and Secondary stage rows with a timeline; a stage can open its Tertiary items.
  • Swappable — heading + Collapse over a .Swappable Content slot.

Behaviour in this kit

  • Collapse turns the panel into the 52px rail; Expand restores it.
  • The stage marker (Completed / Current / Future) is data, not selection — clicking does not change it.
  • The active row gets aria-current="page".

Accessibility

Structure

Wrap the panel in <nav aria-label="…">. Rows are links (or buttons for stages that open children). The stage with children is a disclosure: aria-expanded + aria-controls. Collapse/Expand sets aria-expanded on its button.

Keyboard

Tab enters the panel; ↑ ↓ Home End move between visible rows; → / ← open and close a stage; Enter / Space follow the link. Disabled rows (aria-disabled="true") are skipped. Focus ring added in review, not in Figma.

Stage markers

The Completed / Current / Future marker is visual only. Put the state in text too, e.g. a visually hidden “Completed” in the row label, and aria-current="step" on the current stage if that is the page meaning.

Open issues

  • Figma page is marked in progress (✏️) — values may still change.
  • .Menu Primary Hover text is #0078DD, off-token (next to --pando-blue #0076DD). Kept as a component token.
  • .Menu-Item sub text #737373 and .Swappable body text #000000 are off-token.
  • Warning-Circle on this page is orange #FF8C54 with a #515151 glyph; the kit icon is red #E25757 / white. Recoloured by CSS here — atom variant missing in kit.
  • .Swappable Content icon is the kit refresh-line (20px, icons/refresh-line.svg).
  • The Secondary “Active” variants use the .State “Current” marker; the .State set also has a “Selected-Input” instance under the Completed marker. Only the visible marker is built.
  • Figma’s .Menu Location property only changes the opacity of the dashed line above (First) or below (Last); “Default” exists only for Primary.
  • The Tab Group in the Menu-type panel uses 15px side padding; the Header set uses 20px (kit default).
  • Text line-heights are Figma “auto”; built with .type-12-semibold (17px). Rows are fixed 32 / 46px so heights match.
  • Collapsed=Yes: the “Expand” label looks dark in the Figma render; built with the kit Text Button colour (--pando-blue).
  • CSS dashed borders cannot draw Figma’s exact 1 / 4 dash pattern.
  • Figma has no focus state; the 2px --pando-blue ring is drawn inside the row (offset −2px) because the panel clips overflow.
  • Figma has no selected style for a Secondary stage beyond its marker, and no hover for Secondary rows.
  • Contrast below 4.5:1 on #F3F6FC: Disable #A3A3A3 2.3:1 · Active / collapsed heading #0076DD 4.2:1 · Hover #0078DD on #E9F1F5 3.9:1 · sub text #737373 4.4:1. Non-text below 3:1: Future marker #CBD4D8 1.4:1, Warning #FF8C54 2.1:1.
