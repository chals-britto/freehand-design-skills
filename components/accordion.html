Accordion

The Accordion is a collapsible content container that allows users to progressively show or hide related sections of information. It reduces cognitive load by keeping the UI clean and scannable — users expand only the content they need.

Usage

Text below is from the Figma documentation frames on the Accordion page.

Which type

  • Vertical — best for data tables and detail panels where users browse selectively.
  • Slideout — best inside navigation drawers with grouped menu items. Communicates direction with arrows.
  • Page — best for dashboards where entire sections can be toggled. Includes swappable content slots.

Theme & details

  • Light theme by default. Dark theme only in dark-mode sidebars or on dark backgrounds.
  • Use inline metadata headers for data grids so users can scan without expanding every row.

Do

  • Use when content sections are long and users may only need specific parts.
  • Keep accordion headers short, clear, and scannable (ideally under 5 words).
  • Use Vertical for page body; Slideout for navigation panels; Page for section grouping.
  • Use Additional Details = True to show metadata that helps users decide to expand.
  • Maintain consistent accordion types within the same context.

Don’t

  • Nest accordions more than 2 levels deep.
  • Use for content users always need to see — show it directly instead.
  • Place critical actions or alerts inside collapsed content.
  • Truncate important header info just to force expansion.
  • Mix Vertical and Slideout types in the same list.
  • Use when only 1–2 items exist — just show the content.

Accessibility

Header is a button

Each header is a <button> with aria-expanded and aria-controls. Tab reaches it; Enter or Space toggles it. The panel is a labelled region. Figma: “Headers must be keyboard-focusable. Use aria-expanded to communicate open/closed state.”

Header slots are visual only

The switch, checkbox and tags in the header are drawn, not interactive, because controls can’t sit inside a button. A real control there needs a split header (open issue).

Open for the accessibility pass

Dark closed title 3.6 : 1 · Page action 3.0 : 1 · Light toggle icons 1.7–1.8 : 1. No focus style in Figma (browser default ring shown). Kept as Figma for now.

Open issues

  • Light Slideout hover arrows point the other way to their resting state (Closed · Hover ←, Open · Hover →). Built as drawn.
  • Missing states: no Hover for Vertical · Light · Open, Vertical · Dark or Page; no Dark Page; no Additional Details for Slideout or Dark; no focus, pressed or disabled.
  • Slideout · Light · Closed title is #234357; the other Light Slideout states use #313131.
  • Slideout · Light · Open · Hover indicator is #EEF2F4 — barely visible on #F8F8F8.
  • Page title is an unstyled fill (#005399); Page action uses the temporary style “Temp/ Greyblue” (#6D8EB4).
  • Off-token colours: panel body text #000000; boxed minus #404040; Dark Slideout Open background is #24242F at 80%.
  • Type: title tracking 0.3px (the .caps class uses 0.5px); Figma line-heights are “auto” vs the type classes; the Page header with details is 28px tall (heading line-height 16) instead of 31px.
  • Page header always shows an “ACTIVE” switch with no property to hide it. A hidden “Status/Indent Type” icon and “Pointed Tag” have no property — not built.
  • Vertical and Slideout have no content panel in Figma — the panel shows whatever content is passed.
  • Secondary text colour in Dark is never set in Figma (always hidden); #234357 is used.
  • The Figma documentation frames disagree with the component (hover bg, header text colour, dark bg, Slideout bg, “content bg #F8F8F8”) and ask for a 200ms ease-in-out transition — not built. Three near-duplicate doc frames and loose fragments sit on the page.
  • Contrast below 4.5 : 1 — see Accessibility.
