Try it

Hover a rail icon to show its fly-out; click to pin it. Settings and the avatar show a tooltip. Expand Setup / Shipments in TMS. Keyboard: Tab into the rail, ↑ / ↓, Enter or → to go into the fly-out, ← / Esc to come back, Esc on the rail closes the menu.

The opener is the product’s own (e.g. a Side Nav or header button) — Figma has no opener in this set.

Usage

Three levels

Rail icon = module (Analytics, Master Data, Procure, Planning, TMS, FAP, Integrations, Settings). Fly-out = its pages (.Secondary menu). A group (Arrow / Multiple) opens a third level.

Modules without a fly-out

Settings (and Profile) have no fly-out in Figma; they show a tooltip with the name instead.

Section labels

In the TMS examples, “Planning” and “Execution” are rows whose text is blue — labels that split a long fly-out. They are an instance override in Figma, not a variant.

User and logout

The avatar sits at the bottom of the rail; the name, role and Logout sit at the bottom of every fly-out.

Accessibility

Structure

<nav aria-label="Main menu">. Rail icons are buttons with aria-label; modules with a fly-out carry aria-expanded + aria-controls. Groups are disclosure buttons; pages are links. Not an ARIA menu — it is site navigation.

Current page

The current page link gets aria-current="page"; its rail item gets aria-current="true" and the Active fill. Figma has no visible “current” state for rows.

Keyboard

Rail and fly-out are one Tab stop each (Logout is its own). ↑ / ↓ wrap, Home / End. Enter / → open, ← / Esc go back, Esc on the rail closes the menu and returns focus to the opener. Added in review — not in Figma.

Open issues

  • No visible “current page” state for fly-out rows: .Secondary menu State=Active looks the same as Default (only the name differs). Current page is marked for screen readers only.
  • .Menu-Heading Hover is identical to Default.
  • Type=Multiple (expanded) has no caret and no collapse affordance; the kit collapses on click / ← (added in review — not in Figma).
  • The rail has a Planning item but the set has no Type=Planning; built as a direct link with tooltip “Planning” (icon name).
  • Section labels (blue “Planning”, “Execution”) exist only as text overrides in the TMS variant and the 2 loose examples.
  • TMS variant is inconsistent: mixed indents (75 / 80 / 86), some sub-menu lines dashed [2, 2], the fly-out overflows 718 and its .Name row is missing. The kit uses the clean structure from the loose examples.
  • Figma fly-out rows are mixed width (Single stretched to 250, Multiple 200, third level 184); the kit stretches every row to the fly-out width.
  • Type=Default Profile frame has 15px top padding (75 tall); every other Type has 10px (70) — kit uses 70.
  • Text Avatar fill here is #EEF2F4; the kit Text Avatar is #FFFFFF — atom variant missing in kit, overridden in main-menu.css.
  • Kit Text tooltip is a fixed 164px; Figma rail tooltips hug (57–65px) — hug width added via .pds-main-menu-tip (atom variant missing in kit).
  • .Logout Hover fill is #E9F1F5 but the linked style is named “Accent/Light-Highlight-#EFF3F5”.
  • Line heights: Figma rows use 12px “auto” (16px); .type-12-semibold is 17px — rows keep 16px so they stay 36 tall. Name uses 12/16 vs .type-12-regular 17.
  • The two “Arrow Expand Hover” rows (184 wide, with caret) are not used in any Type; there is no fourth level, so they are built as static rows.
  • No elevation or scrim between the open menu and page content in Figma.
  • No hover/active state for the Close item or the avatar beyond the shared .Menu-Item fills; no focus states anywhere (focus ring added in review).
  • Contrast: Hover fill #E7E7E7 @ 30% on white is ≈1.1 : 1 and Active #F3F6FC on white ≈1.1 : 1 — below 3 : 1 for state changes. Kept as Figma.

Industry gaps — not added

  • Every sub-menu group marked with a chevron, open or closed (Figma drops the caret when a group is expanded). Carbon UI shell left panel
