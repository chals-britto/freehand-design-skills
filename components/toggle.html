Usage

Figma's own text. Template filler and the placeholder block are listed under Open issues.

When to use

A toggle is used to view or switch between enabled or disabled states. The result of changing the toggle state is immediately effective and there's no need for an additional action to apply or save a change.

When not to use

  • Switches can only be on or off. Indeterminate switches don't exist in accessibility APIs. If you need to show a partial state, use a checkbox instead of a switch.
  • Don't use to present critical information or request required input needed to complete a workflow.

Placement & convention

Either a Label text must be placed before a toggle to clarify the action that the toggle performs, or an Action text to describe the binary action of toggle needs to be present, so that the action is clear. Action text must be three words or less and is displayed on the side of a toggle.

Accessibility

Switch

<button role="switch" aria-checked>. Space and Enter flip it. Name it with the visible label, or with aria-label when the label is hidden. The Yes / No action text is aria-hidden because the state is already announced.

Figma: “If using a switch with an icon, use a hidden text label to identify the switch's purpose to screen readers.” · WCAG 2.2 · 4.1.2

Toggle Tab and Icon Tab

role="radiogroup" with role="radio" options. One tab stop; arrow keys move and select. Icon Tab cells carry aria-label (Road, Ship, Air).

Open issues

  • The published Toggle set holds three different components (Switch, Toggle Tab, Icon Tab). They should probably be separate components; Toggle Tab and Icon Tab are segmented controls.
  • The wrapper set exposes only Type. Theme, State, On/Off and Label live on hidden base sets.
  • Switch OFF does not use --color-toggle-off (#CBD4D8); it uses #F9FAFA + #6C6C6C.
  • Switch ON track #D5F9D1 @ 40% is an opacity style not in tokens.
  • Light disabled ON keeps the full-strength green knob; disabled text is #6C6C6C, not --text-disabled.
  • Dark gap is 6px vs 5px in light. Dark disabled ON and OFF are identical colours. Dark knob has a 0.825px same-colour stroke (not built).
  • No hover, focus or pressed state is drawn, but the Figma Behaviour text says: “The keyboard focus state takes the switch's visual hover state and adds a blue ring to the switch in focus.”
  • Action text is stored as “YES”, “Yes” and “No”; uppercase hides the difference.
  • Line height: action text and label use auto (~14px) and 0 tracking; .type-10-* is 10/12 + 0.5px. Tab text auto (~16px); .type-12-regular is 12/17.
  • Toggle Tab: two options only, fixed 69px width. Inner shadow is not a --shadow-* token. Dark: #484858, its 50% style, and the unstyled #D9E6FF fill are not tokens.
  • Icon Tab: dark only, no light version; icons are hard-wired to transport modes; no visible labels.
  • Docs filler — Overview first paragraph: “Toggle/ Switch is a clear and concise label that provides a general introduction or summary of the toggle's purpose. It effectively sets the context for users.” (describes the heading, not the component).
  • Docs filler — When not to use first sentence: “This label effectively conveys the situations in which the toggle should be avoided. It's clear and straightforward.”
  • When to use paragraph is duplicated in Figma. Overview typo “For examples”.
  • Older .documentation block (3195:1953) is still titled with the placeholder “Name”, duplicates the newer section and has an empty “Variation Examples” heading.
  • Do / Don’t tiles have no captions; example pins 1 and 2 have no notes; example screenshots are images (not readable).
  • Switch spec frame has no anatomy panel. Hidden leftover Navigation/Selected instance in Light / Yes / Disabled (8323:2124).
