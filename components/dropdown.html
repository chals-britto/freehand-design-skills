Dropdown

The open menu of a dropdown: an optional search header, grouped options, and a single- or multi-select list. The closed field that opens it is “Input – Dropdown Select” on the Inputs page.

Try it

Click the field to open the menu, pick an option, click outside or press Esc to close. Type in the search to filter. The field is a stand-in drawn from “Input – Dropdown Select” (Inputs page) so the menu has something to open from.

Usage

The Figma page has no written documentation and none was added in review. Below is only how the built component behaves.

Opening and closing

  • Opens from the field (“Input – Dropdown Select”), directly below it.
  • Closes on outside click or Esc.
  • Single select: picking an option closes the menu.
  • Multi-select: the menu stays open; each pick toggles a check. added

Search

  • The search header filters options as you type.
  • Group headers with no matching options are hidden.
  • No matches: an empty message is shown. added
  • Loading: a message replaces the options. added

Long lists

  • Menu: scrolls after 264px (the published list height). added
  • Panel: scrolls after 280px, with the Light scrollbar.

Accessibility

What the code exposes

The list is role="listbox" (with aria-multiselectable for multi-select); each option is role="option" with aria-selected; disabled options carry aria-disabled. The field gets aria-haspopup, aria-expanded and aria-controls from pdsDropdown.attach.

Deferred to the accessibility pass

Arrow-key movement through options, a visible focus ring, and hover state. Options can be picked with the pointer only for now.

Sources: WCAG 2.1.1 · WCAG 2.4.7

Open issues

  • No closed trigger on this page. The closed field is “Input – Dropdown Select” on the Inputs page (component set 3535:3521: Empty / Filled / Active / Open / Error / Disabled, sizes 200 / 225 / 400). It is referenced, not rebuilt here. Its Open state shows a different menu, “Dropdown Light” (3154:2534, Inputs page), not this Filter Dropdown — the two menus need reconciling.
  • Error and disabled field (review: add) exist only on the Input trigger (State=Error 288:492, Disabled=Yes 2207:879), so they are not built here. The menu itself has no error state. Disabled option is added.
  • Copy needed: the empty-search and loading messages have no Figma text. The page shows “[…copy to confirm]” placeholders.
  • Selected option is shown by colour + weight only (#0076DD on white 4.53:1; vs #404040 neighbours 2.29:1). Kept as Figma.
  • Search divider #C8CED5 on white is 1.59:1 (below 3:1). Kept as Figma.
  • Multi-select panel: selected row fill #F8F8F8 vs white is 1.06:1 — only the check carries the state.
  • The 17px blue line under the search placeholder is a drawn shape; unclear if it means “focused”. Drawn always, as in Figma.
  • Off-token colours kept: #404040 option text, #C8CED5 divider, #737373 secondary text, #D7F3F6 / #006064 depot icon, and the three shadows (none match --shadow-1..4).
  • Line heights: Figma uses Auto on all text. Options use .type-12-regular (17px) vs Figma ≈16px, so each option row is 1px taller; group header uses 12px vs Figma 14px auto; secondary line uses .type-10-regular (12px) vs Figma 14px.
  • Menu width is fixed at 150px; long labels are truncated with an ellipsis (no Figma rule).
  • Panel corner radius could not be read (the background is a vector with mixed corners); drawn square.
  • Max height: the review suggested ~256px; 264px is used so the published sample does not scroll.
  • No hover state anywhere in Figma (hover + focus deferred with keyboard a11y).
