Usage

Overview

Tables display tabular data in a basic grid composed of cells, columns, and rows. This format makes it easy for users to scan and compare large amounts of data.

Source: Figma .documentation (2385:6833)

Uses

  • Display tabular data for comparison.
  • Display structured content, where each entry has the same attributes.
  • Let users review, enter, edit, or filter granular data sets.
  • Display a data set that will continue to grow

Source: Figma .documentation

Placement & convention

Table cell can be used to individually place text, dropdown values or tags.

Source: Figma .documentation

Accessibility

Real table markup

Use <table>, <th scope="col"> and <td>. The scroll area is a focusable role="region" with a label, so keyboard users can scroll it with the arrow keys (focus outline added in review — not in Figma).

Selection & sort

Every row checkbox has a label (“Select row 1”), the header one “Select all rows”. Selected rows get aria-selected. Sort buttons are labelled “Sort by …” and the sorted <th> carries aria-sort.

Loading & empty

While loading, the grid has aria-busy="true" and the skeletons are hidden from assistive tech. The empty art uses its Figma hidden text as alt (“no records”).

Open for the accessibility pass

Inherited from Table Cell: Dark header text #8A8A9E on #343440 ≈ 4.0 : 1; Dark disabled #8A8A9E on #393945 ≈ 3.8 : 1. Sort icon Default #E7E7E7 / #B5C3CB on white is under 3 : 1 (non-text). Selected rows have no visual other than the ticked box.

Open issues

  • Row and Table sets are marked “FOR REFERENCE”. Built as a composed pattern (.pds-table), not as a component with its own cell styling.
  • No Dark table in Figma. The Dark composition is built from the Dark Table Cell variants; frame border = the Dark cell line (#8A8A9E @ 50%) — not in Figma.
  • Selection, sort states, sticky header, horizontal scroll, loading and empty are added — none is drawn on the Table page. No selected-row, hover or focus-row style exists; selected rows look the same as unselected ones.
  • Sorted states use the kit icons Navigation/Sort · Ascending (Small -> Big) / Decending (Big -> Small); Table Cell itself only uses Sort Default.
  • Figma sample data is “Some Text” everywhere, so sorting the reference data shows no change. The demo’s first column is Input Text (as in Using Columns) — type in it to see rows move.
  • Row reference frame fills look swapped: Type=Row frame is #F9FAFA and Type=Alternate-Row frame is #FFFFFF, while their cells are Default and Alternate. Invisible (cells cover the frame); built from the cells.
  • Disabled exists only for Text and Input Text cells, so a disabled row with Tag or Dropdown cells has no Figma look. Dark disabled rows differ from Dark Alternate rows by text colour only.
  • Child only exists for Light Text cells — no Dark Child row and no Child Input Text.
  • Empty state: Figma has no table empty layout; the kit art sits centred with 15px padding (added). The art has no title or body text (see Empty State).
  • Loading: no table skeleton in Figma; the kit Skeleton (38 high, two bars) sits in each 50px Text cell.
  • Line heights inherited from Table Cell: 12px text 16 (type scale 17); header 10 SemiBold ≈ 14 (type scale 12).

Industry gaps — not added

  • Sticky (frozen) first column when scrolling sideways — not shown in Figma, not built.
  • Row hover always on, to help scan across a row — Carbon Data table
  • Batch-actions toolbar that appears when rows are selected — Carbon Data table
  • Unsorted arrows shown only on hover; only the sorted column shows its icon — Carbon Data table
  • Pagination at the bottom, sized to the row height — Carbon Data table
  • Expandable rows (Figma has a Child row but no expand control) — Carbon Data table
  • Column picker (kit Column Picker) — not drawn with the table in Figma, not wired here.
