Other open issues

  • Layout shift (newer): the Button Group is hidden at rest (Default 176 high) and shown on Hover/Active (184 high), so the card grows 8px on hover. The hidden instance in Default is also a Normal-size Button Group (226×30), not the Small one (198×24).
  • Button Group size (newer): Figma places Small (24px) buttons in the Button Group, whose kit default is Normal (30px). Kit buttons used with .pds-button--small; the group’s 30px min-height is reset inside the card.
  • Fields overflow (newer): 4–6 inputs of 200px wrap inside a 570px row, so only 2 fit per row and 170px is left empty. Adjacent borders are doubled (gap 0, inside strokes); the older set overlaps them by 1px instead.
  • Atom variant missing in kit — Text Input Field (older): the remote Text Input Field uses label #616161, placeholder #737373, value #404040 (all off-token) and a 5px icon gap. Built as the kit Input - Text with scoped overrides (.pds-actions__tif).
  • Atom variant missing in kit — refresh-line icon (20px) in the swappable slot. Inlined, same path as tooltip.js.
  • Label room: the kit input reserves 16px after the label for an info icon; removed inside Actions fields so “Booking Confirmation Number” fits as in Figma.
  • Date format: Figma samples read “19 Jan 2023 - 10:00 AM”; the kit Calendar writes DD-MM-YYYY. Not reconciled.
  • Save enable rule (older): Figma shows only Empty (Save disabled) and Filled (Save enabled). Built as “enabled when every field has a value”; confirm for two-field cards.
  • Secondary button meaning (newer): both buttons read “Button Text”. Built as Cancel (leaves Active, fires cancel) + Submit; confirm.
  • Hidden layers (older): a “Document” row (EPOD Copy + Misc/Add-Attachment) in Mark as Delivered and an “Edit” button in every variant are hidden and not exposed as properties. Document row built as an opt-in part; Edit not built.
  • Label typo: “PRO NUmber” in Figma (renders “PRO NUMBER” because labels are upper-cased). Kept. “pickeup” typo in the Alert text kept.
  • Line heights: title 12 SemiBold is AUTO (16) in Figma vs .type-12-semibold 17px; Alert and slot text are 12/16 vs .type-12-regular 17px (set to 16px in the component).
  • Off-token colours: slot body text #000000; GeoFence-Input icon #9C9C9C; Text Input Field greys above.
  • Contrast (deferred): Primary disabled “Save” #616161 on #E7E7E7 ≈ 4.6:1 passes barely; placeholder #737373 on white 4.7:1; GeoFence icon #9C9C9C on white 2.7:1 and Calendar icon #A3A3A3 2.5:1 (non-text, below 3:1); #9CD2FF card border on white 1.6:1.
  • Missing states: no error/validation state on any Actions variant, no loading/submitting state, no focus ring. Focus ring added in review on the card only (not in Figma).

Try it

Newer set: hover a card to see its buttons; click or tab into one to make it Active — only one card in a stack is Active. Esc or the secondary button leaves Active. Older set: type into the fields — Save turns on when every field is filled; Clear empties them. Date fields open the kit Calendar. The Document row’s Add tile opens your file picker (names only, nothing is uploaded).

Usage

Overview

It enables users to take actions on the page.

Figma .documentation

Usage

  • As a Form (inputs)
  • Recommendations
  • Highlighted information

Figma .documentation

Interaction

  • Supports hover and active states.
  • Active state style will be same as Hover state.
  • When multiple action cards are stacked, only one can be active at a time.

Figma .documentation · Placement & Convention: NA · Animation: NA

Accessibility

Structure

Each card is a role="group" named by its header (aria-labelledby). Fields are the kit inputs with real <label>s; buttons are kit <button>s.

Keyboard

Tab into a newer card to make it Active and reveal its buttons (:focus-within), so keyboard users reach them. Esc leaves Active. Date fields open the Calendar with ArrowDown or click.

Status

The Alert row uses role="alert". Disabled Save uses the native disabled attribute. Contrast failures are listed under Open issues.

Industry gaps — not added

  • Inline field errors on blur, cleared once met — no error state in either set. Carbon Forms
  • Disable the primary button during submission to prevent double submits (loading state). Carbon Forms
  • Buttons at the bottom of the form, not top-aligned — both sets put them in the header. Carbon Forms
  • Task-specific button labels instead of generic ones (“Button Text”). Carbon Forms
  • Mark required or optional fields consistently — no marking in either set. Carbon Forms
